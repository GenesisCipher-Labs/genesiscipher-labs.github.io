THE AGGREGATERATING DECISION — READ BEFORE "FIXING" THIS There is deliberately no aggregateRating property below, and adding one would be a mistake. Pact's rating count is in the low single digits — measured the same day as 1 via the iTunes lookup API and 2 on the App Store product page, which is itself the point: it is small enough to move on a single review. Google requires that a rating declared in markup be sourced from users and be VISIBLE on the page carrying the markup; neither holds here. Beyond compliance, a five-star average over one or two ratings reads as fabricated to a human and carries no weight with a ranker. Apple's own product page already publishes a real SoftwareApplication aggregateRating for this app, so the correct move is `sameAs` pointing at it and no rating of our own — let the authoritative source carry it. This is the same rule the app itself follows when it omits a GSTIN, an LUT or a place of supply it was never told, rather than printing an assumption. Revisit only when the rating count is in the dozens AND the rating is rendered on this page. Also deliberately absent, for the same reason — add each only when the fact exists: `logo` on Organization (no logo asset is hosted here), `softwareVersion` (it would be stale the day after any release), `address` and `foundingDate`, `sameAs` social profiles, and any `review`. ================================================================================ {%- endcomment -%} {%- assign url = page.url -%} {%- assign in_pact = false -%} {%- if url contains '/pact' -%}{%- assign in_pact = true -%}{%- endif -%} {%- assign is_pact_home = false -%} {%- if url == '/pact/' -%}{%- assign is_pact_home = true -%}{%- endif -%} {%- assign is_faq = false -%} {%- if url == site.data.faq.page_url -%}{%- assign is_faq = true -%}{%- endif -%} {%- assign is_home = false -%} {%- if url == '/' -%}{%- assign is_home = true -%}{%- endif -%} {%- assign pact = site.data.pact -%} {%- comment -%} Favicon.
